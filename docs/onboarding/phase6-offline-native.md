# Phase 6 — Local drafts, native entry and account synchronization

The native entry now opens the book welcome and feature carousel. Students can create a setup draft before signing in, including offline, or use the existing login/provider/guest paths. A retained installation draft resumes at its saved step. Passwords, OAuth proofs and session tokens never enter these drafts; native authentication continues to use SecureSession.

Native drafts use the existing SQLite `local_meta` table with scoped keys; web drafts use a dedicated IndexedDB store. Valid choices, Back navigation and confirmed step transitions save locally without waiting for network I/O. Unconfirmed review edits remain an edit session and require Save changes; Cancel/Back restore the previous review. Storage errors are displayed and block false success. Conditional writes protect competing windows. Native SQL compares stored text and does not depend on SQLite JSON extensions.

An installation draft is separate from every account. An authenticated empty, incomplete account can explicitly move the device choices after a prompt. The handoff atomically checks source and target versions, writes the account draft and removes the unassociated source. It never migrates guest study records, copies another account's draft, overwrites existing setup choices or reopens a completed account. Account removal clears its onboarding metadata; full native data removal wipes the database.

The authenticated onboarding GET supplies the current account ID, completion state, versioned/legacy resume state, study goal and verified catalog. A first-run device has no verified catalog and offers Not decided yet; after refresh, each account retains its verified choices locally. Cached choices remain subject to server revalidation. Withdrawal returns the affected choice for review, keeps unrelated preferences and cancels automatic completion.

The coordinator keeps disk writes independent of network waits. A sent snapshot is retained to recognize an exact lost reply while preserving newer local edits. Fresh metadata precedes replay, and revision checks reject external changes. Both versions of a conflict stay local for explicit review; account choices remain active by default. Reviewing a device version does not automatically submit it. Account mismatches pause outbound work. Reconnect, foreground resume and the native sync signal trigger bounded replay; the web shell also resumes retained setup work after verifying the current account. Unassociated/demo drafts never trigger account requests.

Finish offline says Saved on this device / Account setup pending sync. It becomes account-complete only after a valid server acknowledgement or an authoritative completed profile. Retries respect Phase 4's atomic completion and already-completed no-op. Existing completed native accounts skip academic setup without redirecting their current app route. Credential setup retains its own priority above the academic screen.

The native bundle includes stationery and book SVGs with a SHA-256/byte manifest, and uses system fonts without remote font requests. The public `/onboarding-offline-preview` demonstrates persistent demo-only choices with no account requests; `/onboarding-preview` remains the disposable live-catalog design preview. A browser page's cold offline availability depends on the existing web cache; native welcome/setup code and assets are bundled locally.

Tests cover local reopen/finish, simultaneous edits during network I/O, lost draft/completion replies, stale windows, cloud/device conflict review, account isolation, atomic handoff and guarded source removal, catalog withdrawal, SQLite compare-and-set, secret-field rejection, stop-on-account-change and bundle asset integrity. Phase 7 remains full phone/tablet/desktop certification, actual APK packaging and install tests.
